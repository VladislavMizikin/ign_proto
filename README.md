# IGN Protocol Library

---

## 1. Обзор

**IGN Protocol** — лёгкая встраиваемая библиотека на C для реализации бинарного фреймированного протокола с CRC32 и расширяемым пространством команд.

Библиотека ориентирована на:

- MCU (bare‑metal / RTOS)
- Bootloader / сервисные интерфейсы
- UART / RS‑485 / TCP туннелирование
- Строгий контроль памяти (без динамического выделения)

Ключевые свойства:

- Потоковый парсер (byte‑by‑byte)
- Streaming CRC32 (через пользовательские callbacks)
- Разделение transport / protocol
- Метрики работы протокола
- Поддержка CORE‑команд (HELLO, HOST_TIME, GET_METRICS)

---

## 2. Формат фрейма

```
[SOF0][SOF1][LEN_L][LEN_H][CMD][PAYLOAD...][CRC32_LE]
```

| Поле    | Размер     | Описание                      |
|---------|------------|-------------------------------|
| SOF0    | 1 байт     | 0xA5                          |
| SOF1    | 1 байт     | 0x5A                          |
| LEN     | 2 байта    | Длина payload (little‑endian) |
| CMD     | 1 байт     | Код команды                   |
| PAYLOAD | 0–512 байт | Полезные данные               |
| CRC32   | 4 байта    | CRC32 (little‑endian)         |

CRC вычисляется от:

```
[LEN_L][LEN_H][CMD][PAYLOAD...]
```

SOF в CRC не входит.

---

## 3. Архитектура

- Framing Layer — формирование фреймов и отправка
- Parser Layer — state machine и проверка CRC
- Command Layer — CORE и пользовательские команды

---

## 4. Инициализация

| Команда     | Код  |

| HELLO       | 0x01 |
| HOST_TIME   | 0x02 |
| GET_METRICS | 0x03 |

---

## 5.1. Политика ответов

В протоколе действует единое правило формирования ответов:

- если команда успешно выполняется и должна вернуть данные, устройство отвечает кадром с **тем же кодом команды**
- если команда успешно выполняется и дополнительных данных не возвращает, устройство отвечает **ACK**
- если команда завершается ошибкой, устройство отвечает **NACK**

Примеры:

- `HELLO (0x01)` -> ответ `HELLO (0x01)` с payload `{"BL", ver}` или `{"AP", ver}`
- `HOST_TIME (0x02)` -> ответ `ACK (0x7E)` с payload `[0x02]`
- `GET_METRICS (0x03)` -> ответ `GET_METRICS (0x03)` с payload структуры `ign_proto_metrics_t`

Форматы служебных ответов:

- `ACK payload = [orig_cmd]`
- `NACK payload = [nack_code][orig_cmd]`

Такой подход позволяет единообразно описывать команды и при этом не вводить отдельные коды ответов для команд, возвращающих полезные данные.
